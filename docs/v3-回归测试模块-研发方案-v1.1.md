## 0. v1.0 → v1.1 变更点
- 用例仅存当前内容和 active/retired；旧修订表停写，只读展示。
- 审批移至基线冻结；基线项保存完整快照，执行绑定基线项。

## 1. 范围与非目标
- 每项目维护功能点、R0–R4 基线、逐轮记录和报告；复用现有用例库，新增和编辑由人工触发。
- 不做自动化调度、CI、步骤级结果、电子签名；不开 R2；证据原件存受控归档，站点仅存引用、哈希和摘要。
- 用例内容：当前标题、步骤、预期、数据引用与功能点映射；历史内容以基线项快照保存。
- 回归基线：一次跑批范围、各用例内容快照与数据清单（`regression_baselines`）。
- 发布版本：产品发版（`releases`）；基线 ≠ 发布版本 ≠ 当前用例内容。

## 3. 流程规则
1. **就地修改判据**：功能点映射与断言意图均不变时，就地修改内容并更新 content_hash，**不新建、不退役**；映射或断言意图变化（拆分/合并/换覆盖对象）时新建用例并退役旧条；功能永久下线时退役，不删除。
2. **编辑审计**：每次内容或映射变更必须在同一事务更新用例、映射和 content_hash，并追加 regression_events 的字段级变更摘要、前后哈希、操作者及时间；审计写入失败则整个保存失败，内容与审计均回滚，禁止静默放行。
3. **基线冻结与选基线**：纳入时复制完整内容及功能点映射并计算 snapshot_hash，固化数据清单及 manifest_hash；审批发生在基线冻结，冻结后不得改，只能新建 revision。开轮显式选择本项目已冻结基线；预填该发布版本最新冻结基线，无则回退通用冻结基线，维护者确认后才能创建。
4. **执行与三态**：按基线项创建执行项并锁定基线；同一发布版本重跑建新轮，保存 build/commit/环境，禁止覆盖旧轮。记录 PASS/FAIL/DIFF；DIFF 须填原因并经账号确认，未签或拒签按 FAIL，获批单列；未执行项阻止关轮。
5. **跨轮对比**：显式选择同项目两次已关闭轮次并按 tc_id 配对，只有 snapshot_hash 全等、manifest_hash 相等且环境/配置一致才可比；旧非失败→失败为新失败，失败→失败为老失败，失败→PASS 为已修复，失败→获批 DIFF 为差异获批；预期变更及其他不满足门槛项列“不可比/预期变更”，不计回归失败。
- 项目内 FP 编号；TC 继续以 counters.tc_code 原子递增，`TC-` 加至少三位数字补零，全局唯一且永不复用。
- 页面显示 `<发布版本号> · 基线 rev<N>`，通用基线显示 `通用 · 基线 rev<N>`；发布版本专用基线不可跨发布版本使用。
- 历史记录保留 ID 和原值，NULL tc_version 不回填、deviation 不转 DIFF；旧数据及旧修订表标 legacy 只读。先备份、演练迁移并对账，失败恢复备份。
- 报告在关轮时存储快照，经批准冻结后不可修改；更正创建新 revision。支持页面、JSON 和浏览器打印 PDF。

## 6. 验收标准
1. 维护者切换项目时只看到本项目资产；使用其他项目 ID 读取报告或创建映射/轮次时看到拒绝。
2. 两个项目并发建用例时看到不同且全局递增的 TC 号；计数器缺失时看到取号失败，已分配号码不复用。
3. 维护者按不变映射和断言意图编辑时看到同一用例及新哈希；改变映射或断言意图时看到新用例和退役旧条，永久下线时只退役。
4. 维护者编辑后看到字段摘要、前后哈希、操作者和时间；注入审计写入失败时，内容、映射及审计均未落库。
5. 维护者新增、编辑或退役用例后检查数据库，看到 test_case_versions 没有新行，旧行与旧批准信息仅供 legacy 只读。
6. 维护者冻结基线后修改当前用例，看到基线快照及哈希不变；修改冻结基线被拒绝，开轮未确认已冻结基线时无法创建。
7. 测试者对同一发布版本执行两轮时看到各自的基线项绑定、build/commit 和独立结果，第二轮不覆盖第一轮。
8. 测试者记录 DIFF 时看到未签/拒签计为 FAIL；确认接受后看到差异获批，原始结果仍为 DIFF。
9. 评审者对比两轮时看到五类结果；预期变更导致快照哈希不同，显示“不可比/预期变更”，不计回归失败；冻结报告拒绝修改。
