## 端点、请求和响应
- `GET /api/runs?project_id=N[&release_id=X]` → `{ok,items:[{id,release_id,release_version,baseline_id,baseline_code,revision,round_no,build_ref,commit_sha,environment,state,created_at,closed_at,stat}]}`；stat 有 total/pass/fail/deviation/diff/empty。
- `GET /api/runs/suggest-baseline?project_id=N&release_id=X` → `{ok,baseline:{id,baseline_code,revision,release_id,scope}|null,candidates:[...]}`；先选该版本最高 revision，再选通用最高 revision，仅 frozen，可选列表按冻结时间倒序；建议不等于确认。
- `POST /api/runs` `{project_id,release_id,baseline_id,build_ref?,commit_sha?,environment?,config_hash?}` → `{ok,id,round_no}`；必须显式指定已冻结基线。
- `GET /api/runs/:id?project_id=N` → `{ok,run:{...,baseline:{id,baseline_code,revision,release_id,frozen_at,manifest_hash,item_count}},stat,items:[...]}`；items 全部来自基线项，未执行项 result 为空，tc_version 来自基线项，标题来自当前用例。
- `POST /api/runs/:id/start` body `{}` → `{ok:true,state:'running'}`；重复 start 不重复写事件，closed 返回 409。
- `POST /api/runs/:id/close` body `{}` → 示例 `409 {"error":"还有 1 条未执行","pending":1,"pending_codes":["TC-003"]}`；`{"confirm_partial":true}` → `{ok:true,stat:{total:2,pass:1,fail:0,deviation:0,diff:0,empty:1}}`，事件 detail 为 `{"partial":true,"pending":1}`。
- start/close 均需 JSON 对象，空操作发送 `{}`；confirm_partial 为可选布尔值。复用现有登录及活动项目校验；提供 project_id 时验证同项目，现有站点没有用户与项目的成员权限表。

## 编号、相容性与关轮
- 源码 `apiRunCreate` 内一条 INSERT 同时计算和写入轮次号（省略参数值）：
```sql
INSERT INTO test_runs(project_id,release_id,baseline_id,round_no,build_ref,commit_sha,environment,config_hash,state,created_by,created_at,updated_at)
SELECT ?,?,?,(SELECT COALESCE(MAX(round_no),0)+1 FROM test_runs WHERE project_id=? AND release_id=?),?,?,?,?, 'planned',?,?,?
WHERE EXISTS (SELECT 1 FROM regression_baselines WHERE id=? AND project_id=? AND state='frozen' AND (release_id IS NULL OR release_id=?))
  AND EXISTS (SELECT 1 FROM releases WHERE id=? AND project_id=?);
```
- 本地执行同一 INSERT 两次：`round_no=[1,2]`；手工重复 1 → `UNIQUE constraint failed: test_runs.project_id, test_runs.release_id, test_runs.round_no`。并发若触发该唯一约束，捕获后返回 `409 并发冲突，请重试`；其他数据库错误不伪装成冲突。
- 相容性校验见 Worker `apiRunCreate` 中 `baseline.release_id!==null && baseline.release_id!==rid`：相同版本允许、NULL 通用允许、其他版本返回 `409 基线与该版本不匹配`；Node 模拟分别得到 200、200、409；数据库 INSERT 的 EXISTS 条件也会阻止错配（本地 `changes()=0`）。
- 关闭前计算缺失执行行及 `result=''` 的条目数和前五个编号；未确认的部分轮返回 409。确认部分轮后，更新的 WHERE 同时比较未执行数量和轮次状态，再以同一个 batch 写关闭事件，避免并发写入造成记录的 pending 数不一致；若变化返回 409 并要求重试。

## 聚合统计 SQL
```sql
SELECT r.id, COUNT(i.id) AS total,
  COALESCE(SUM(CASE WHEN i.id IS NOT NULL AND e.result='pass' THEN 1 ELSE 0 END),0) AS pass,
  COALESCE(SUM(CASE WHEN i.id IS NOT NULL AND e.result='fail' THEN 1 ELSE 0 END),0) AS fail,
  COALESCE(SUM(CASE WHEN i.id IS NOT NULL AND e.result='deviation' THEN 1 ELSE 0 END),0) AS deviation,
  COALESCE(SUM(CASE WHEN i.id IS NOT NULL AND e.result='diff' THEN 1 ELSE 0 END),0) AS diff,
  COALESCE(SUM(CASE WHEN i.id IS NOT NULL AND COALESCE(e.result,'')='' THEN 1 ELSE 0 END),0) AS empty
FROM test_runs r
LEFT JOIN regression_baseline_items i ON i.project_id=r.project_id AND i.baseline_id=r.baseline_id
LEFT JOIN tc_executions e ON e.run_id=r.id AND e.baseline_item_id=i.id
WHERE r.project_id=? GROUP BY r.id ORDER BY r.release_id DESC,r.round_no DESC;
```
- 列表实际 SQL 另 JOIN releases、regression_baselines 返回名称，release_id 过滤按需添加；以上为其统计部分。使用一次聚合查询而非逐轮查询。
