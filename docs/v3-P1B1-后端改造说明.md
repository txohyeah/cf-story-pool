## 端点清单
- `PUT /api/testcases/:id/execution`：必须指定 run_id；只接受 planned/running 的同项目轮次，按基线项和来源版本写入，按轮次与基线项更新。
- `GET /api/feature-points?project_id=`：按项目列功能点与 tc_count，可选 status，默认不列 retired。
- `POST /api/feature-points`：按项目生成 FP 编号并创建。
- `PATCH /api/feature-points/:id`：修改标题、描述及非退役状态。
- `POST /api/feature-points/:id/retire`、`POST /api/feature-points/:id/revive`：退役或恢复功能点。
- `GET /api/testcases/:id`：原有详情增加 feature_points 和 retired。
- `PUT /api/testcases/:id/features`：校验后以 batch 全量替换功能点映射，允许空数组。
- `PATCH /api/testcases/:id`：已批准用例编辑必须填写非空修订摘要；保留版本写入与乐观锁。
- `POST /api/testcases/:id/retire`、`POST /api/testcases/:id/revive`：写入事件并返回 retired，保留原 status。
- `GET /api/testcases/:id/versions`：返回步骤、修订摘要、作者、时间和序号。

## 权限、审计与限制
- 沿用全站登录会话；检查项目存在且 is_active=1，引用关系必须同项目，调用方提供 project_id 时必须与目标归属一致。**现有站点没有用户—项目成员表或可见性函数，现行规则是已登录用户可见所有活动项目；因此不能阻止某登录用户直接访问另一个活动项目，也不能宣称实现了用户级项目隔离。** 项目成员模型需另行设计/迁移后接入，部署前须明确接受或补齐。
- 本 Worker 原本不存在 `auditEvent`，需求表 events 又要求 req_id；本轮新增同名本地 helper，将写入与 regression_events 追加放在同一 D1 batch；test_case 事件记录步骤 SHA-256 前后值。并无第二个独立通用审计库；历史版本仍在 test_case_versions。
- 用例退役临时由该用例最新 retire/revive 事件推导，状态列维持 draft/approved；P1-C 增加 retired_by/retired_at 后应有序迁移和校验事件、切换读取及保留旧事件。旧用例删除入口现返回 409，防止删掉历史执行。

## P1-B1.5 修订（覆盖本说明中旧的 NEED_RUN 和永久禁止删除结论）
- `ux_tce_legacy` 是 `UNIQUE(tc_id,release_id) WHERE run_id IS NULL` 的部分索引：轮次外同用例同发布版本仅一条，可重复 upsert；不限制轮次内记录。必须在迁移脚本执行之前审查旧 legacy 唯一性；已执行旧版迁移的环境需另行安排补建索引，不能重跑整份重建脚本。
- 不传 run_id 时使用 legacy 入口，release 必须与用例同项目，响应 `mode=legacy`；不写 tc_version 或项目/轮次/基线字段。legacy 不携带用例修订，跨版对比不可作为证据，只供日常记录；轮次页上线后标记 deprecated。
- 既有 CHECK 的 legacy 分支实际只要求 project_id/run_id/baseline_id/baseline_item_id 为空，允许旧 tc_version 非空；为避免覆盖已知历史版本信息，此类少见旧行被保护并返回 409，线上预核数据均为 NULL。新建 legacy 行及可更新行五字段均为空。
- 传 run_id 维持现有轮次和基线项校验，响应 `mode=run`；两种写入均追加 execute 事件，detail 分别记录 mode 与 release_id/run_id。`NEED_RUN` 已从 Worker 移除；历史 CP 和测试结果仅表示当时行为。
- 删除时先按 project_id + tc_id 查询所有基线项，任何引用均返回指定 409（包括草稿基线）；无引用时以 batch 删除执行、版本、功能点映射、该用例原事件及用例，再追加 delete 事件并记录删除计数。外键仍阻止删除被其他实体引用的记录。
- 删除计数在 batch 前读取；极端并发写入可能使审计计数与实际删除数不同，后续应结合 D1 事务或串行写入机制消除此竞态。项目级成员权限、轮次页与 DIFF 签字等既有 TODO 仍未完成。
