# P1-F1 报告与跨轮对比

## 接口契约

- `GET /api/runs/:id/compare?against=N&project_id=N`：同项目轮次比较；返回 comparable、reasons、pairs，满足门槛时附 summary。
- `POST /api/reports`：`{project_id,run_id,comparison_run_id?,template_version?}`；已关轮才能创建，返回编号、revision 和快照哈希；存在 draft/approved 时 409。
- `GET /api/reports?project_id=N[&run_id=N]`：返回报告摘要、counts 和 pass_rate，不返回用例明细。
- `GET /api/reports/:id?project_id=N`：返回报告摘要、snapshot_json 原文、snapshot_hash 和批准／冻结人。
- `POST /api/reports/:id/approve|freeze|revision`：body 含 project_id；更正可带 note；更正返回新 id 和 revision。批准与冻结分别记操作者及时间。
- `GET /api/reports/:id/export?project_id=N&format=json`：附件下载原始 snapshot_json，不套额外对象。

## 状态与隔离

`draft → approved → frozen → revision 新 draft`；批准已批准报告幂等，草稿冻结与冻结后批准返回 409，只有 frozen 可更正。原报告不变，更正重算快照。报告创建和更正通过 INSERT 守卫限制同轮未冻结报告；编号使用 `report_code:<project_id>` 原子计数器，竞争失败可能跳号但不复用。数据库唯一键处理并发 revision 冲突。

项目、轮次与报告均按 project_id 校验；跨项目返回 404。生成报告前必须关轮；对比轮只要求同项目并通过可比门槛。无报告编辑端点：若需更正已冻结报告，使用 revision。

## 确定性快照

对象键递归按字典序排序，数组按原顺序，JSON 紧凑编码；用例数组按 tc_code 升序。使用原文 Unicode 和 JSON 字符串转义，生成时间由 `nowIso()` 写入。实现：
```js
function canonicalJson(value) {
  if (Array.isArray(value)) return '['+value.map(canonicalJson).join(',')+']';
  if (value!==null && typeof value==='object') return '{'+Object.keys(value).sort().map(k=>JSON.stringify(k)+':'+canonicalJson(value[k])).join(',')+'}';
  return JSON.stringify(value);
}
```
外部拿 `snapshot_json` 原文按 UTF-8 原样写入文件（不要添加换行、重新格式化或转义），执行 `sha256sum snapshot.json` 即得 snapshot_hash。空执行集 pass_rate 为 0；有执行时有效通过数除以有效执行数，四舍五入到 4 位小数。

## 对比口径

三项门槛必须全部相等：environment、config_hash、基线 manifest_hash；不相等直接返回原因与空 pairs。可比时按 tc_id 配对。有效结果：pass 和获批 diff 为 pass；fail、deviation、拒绝或未签 diff 为 fail；空结果为 empty。

| 分类 | 判定，按从上到下的优先级 |
|---|---|
| new_fail | pass → fail |
| old_fail | fail → fail |
| fixed | fail → pass |
| diff_accepted | 上述未命中，且本轮 diff 为 accept |
| not_comparable | 两侧均空、单侧缺失及其他未命中；单侧缺失带 only_in_before/only_in_after |
