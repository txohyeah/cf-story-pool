# 回归测试模块研发方案 v1.0
## 1. 范围与非目标
- 每个项目维护自己的功能点、R0–R4 用例基线、逐轮记录和报告；复用现有用例库。
- 人工新增与改版；不做自动化调度、CI、步骤级结果、电子签名；不开 R2。
- 截图/日志/断言 JSON 存受控归档，站点只存清单、定位符、哈希和摘要；现有需求附件限制不变。
- 用例版本：单条用例的第几版（`test_case_versions.version`）。
- 回归基线：一次跑批的范围、每条用例所用版本及数据清单（`regression_baselines`）。
- 发布版本：产品发版（`releases`）；基线 ≠ 发布版本 ≠ 用例版本。

## 3. 流程规则
1. **用例改版与状态**：人工建用例/新修订，按 draft→approved→frozen 流转；批准后禁止改正文，修改须另建草稿。只依据版本 state 判批准/冻结，test_cases.status 和旧接口返回值由当前版本派生；退役不删历史。
2. **功能点与映射**：按项目维护 FP- 编号与用例多对多，需求只作可选追溯；功能点映射、标题、步骤、预期及数据清单随版本快照保存。
3. **基线冻结与选基线**：只将已批准/冻结且快照完整的用例版本加入基线；冻结后禁止修改，只能新建 revision；开轮必须显式选本项目已冻结基线，执行锁定其中的用例版本。新建轮次预填该发布版本最新冻结基线，无则回退到通用冻结基线；维护者一键确认，不得静默跳过确认。
4. **轮次与三态**：同一版本单重跑建新轮，锁定 build/commit/环境，禁止覆盖旧轮；记录 PASS/FAIL/DIFF，DIFF 填原因并由账号确认，未签或拒签按 FAIL，获批单列；未执行项阻止关轮。
5. **跨版本对比**：显式选同项目两次已关闭轮次，按 tc_id 配对且用例版本、预期哈希、环境/配置可比：非失败→失败为新失败，失败→失败为老失败，失败→PASS 为已修复；失败→获批 DIFF 为差异获批；缺失/新增/移出/不满足可比条件列不可比。
- 全局 TC 号继续用 `counters.tc_code` 原子递增，格式 `TC-` 加至少三位数字补零，永不复用；项目内只为功能点分配 FP- 编号。
- 旧数据保留原 ID、原值；NULL tc_version 不回填、deviation 不转 DIFF，标 legacy 只读；迁移前备份，重建执行唯一约束后对账，不通过则恢复备份。
- 报告以关轮时数据生成快照，批准并冻结后不可改；修正创建新 revision。展示页面、JSON 导出和浏览器打印 PDF，记录操作者、时间和哈希。

## 6. 验收标准
1. 维护者切换项目时只看到本项目资产；用其他项目 ID 调接口创建映射、轮次或读取报告时看到拒绝。
2. 两个项目并发新建用例时，各自看到不同且全局递增的 TC 号；计数器缺失时看到取号失败，恢复后已分配号码不复用。
3. 维护者批准并冻结用例版本后尝试编辑、删除或走旧接口改状态时看到拒绝；新建修订后看到草稿且原版本不变。
4. 维护者修改已冻结基线时看到拒绝；开轮未选基线或选未冻结基线时看到拒绝，选择冻结基线后看到其锁定版本。
5. 测试者对同一版本单执行两轮后看到两份独立结果和各自 build/commit，第二轮不能覆盖第一轮。
6. 测试者将结果标为 DIFF 时看到未签/拒签计入 FAIL；确认接受后看到“差异获批”，原始结果仍为 DIFF。
7. 评审者对比两次已关闭轮次时看到新失败、老失败、已修复、差异获批及不可比分组；冻结报告后尝试修改看到拒绝，新修订保留原快照。
8. 维护者查看历史记录时看到 legacy、原 deviation 和未知版本标记；尝试修改被拒绝，NULL tc_version 保持 NULL。
9. 同一发布版本有两个基线 revision 且各执行一轮时，评审者在对比页看到两轮用例版本差异归入“不可比”，而非误判为回归失败。
