## 页面结构与状态
- `dist/runs.html` 为单页列表/详情：URL 的 `project` 同步项目栏，`run` 指向详情；创建后用 history 更新 URL 并打开详情，浏览器前进/后退恢复相应视图。
- 列表默认选择 `/api/releases?project=N` 返回的第一条（现有后端按 id 降序，作为最新版本），可切换全部版本；每轮展示状态、基线、build/commit、环境、进度和操作。
- 新建弹窗按版本请求建议；自动选同版本或通用建议，候选项仅显示适用于所选版本的冻结基线；没有建议时红字提示并禁用提交。
- planned 可开始或关闭，running 可关闭，closed 没有修改按钮；未关闭行可展开结果表单，保存后重拉详情。关轮先尝试正常关闭，遇到带 pending 的 409 用 `PoolUI.showConfirm` 展示待执行编号，确认后携带 `confirm_partial:true` 重试。

## API 对照
| 交互 | 方法和路径 | 主要字段 |
|---|---|---|
| 项目与当前用户 | GET `/api/bootstrap`、`/api/me` | projects、display_name/username |
| 版本 | GET `/api/releases?project=N` | items 的 id/version；现有接口使用 `project`，非 `project_id` |
| 列表 | GET `/api/runs?project_id=N[&release_id=X]` | items、state、stat |
| 建议基线 | GET `/api/runs/suggest-baseline?project_id=N&release_id=X` | baseline、scope、candidates |
| 新建 | POST `/api/runs` | project_id、release_id、baseline_id、build_ref、commit_sha、environment |
| 详情 | GET `/api/runs/:id?project_id=N` | run、baseline、stat、items |
| 开始 | POST `/api/runs/:id/start` | `{project_id}` |
| 关闭 | POST `/api/runs/:id/close` | `{project_id}`；部分确认时增加 `confirm_partial:true` |
| 打结果 | PUT `/api/testcases/:id/execution` | run_id、project_id、result、conclusion、dev_ref、ev_ref；保留已有引用 |
- 页面自定义 fetch 返回 `{status,body}`，401 跳登录，JSON 解析失败或网络错误有兜底；错误显示在页面、弹窗或行内的 `.err`，不使用 alert。时间使用基线页的 `fmtAt` 规则。
