## 端点清单
- `GET /api/baselines?project_id=N`：按发布版本、编号、修订排序列出基线、来源版本、条数与哈希。
- `POST /api/baselines`：`{project_id,release_id?,layer,tc_ids,fp_ids?}` 创建 draft；来源用例及功能点均需同项目，排除退役和未批准用例。
- `GET /api/baselines/:id?project_id=N`：基线详情及快照中的编号、标题、分层、来源修订和哈希。
- `POST /api/baselines/:id/freeze`：draft 重算快照与清单后冻结，不接受 approved 状态。
- `POST /api/baselines/:id/revision`：复制源基线的编号、发布归属与条目，使用当前用例重建快照，revision 为源值 + 1；若该修订已存在则返回 409。
- `POST /api/baselines/:id/items`：`{tc_ids:[...]}`，draft 按基线原分层添加；可选 `layer` 指定分层；重复用例返回 409。
- `DELETE /api/baselines/:id/items/:itemId`：仅 draft 删除条目；空草稿无法冻结。
- 路由源码：`/api/baselines`（GET/POST）、`/^\/api\/baselines\/(\d+)$/`（GET）、`/^\/api\/baselines\/(\d+)\/(freeze|revision|items)$/`（POST）、`/^\/api\/baselines\/(\d+)\/items\/(\d+)$/`（DELETE）。

## 规则与边界
- 快照字段按 `tc_code,title,steps_md,risk,ctype,related_req,covers_urs,tc_version,feature_points` 顺序用 JSON.stringify 紧凑序列化；功能点按 fp_code 升序，SHA-256 使用 UTF-8、小写十六进制。
- 清单的哈希输入按 tc_id 升序、每行 `tc_id:tc_version:snapshot_hash`，行间 `\n`，末尾不加换行；数据清单为 `{"items":[...],"generated_at":...}`。
- draft 创建及 revision 的 `manifest_hash` 是 NOT NULL 空串，表示尚未冻结；草稿 data_manifest_json 暂存初始 layer，供不带 layer 的增项请求使用。冻结后才保存真实哈希和清单。
- 单人维护直接 draft→frozen，本轮不启用 approved 状态。快照绑定创建或冻结时的 current_version；用例改版后新版本号变化，已冻结的旧基线仍引用旧版本和原快照。
- 通过 batch 在写入前校验状态、条目集合、用例当前字段/批准/退役、功能点映射；失配的守卫语句触发 NOT NULL 约束使批次回滚。最终冻结 UPDATE 的 `WHERE state='draft'` 为乐观锁，受保护条目增删采用同一批次的状态条件。
- 项目校验沿用既有站点范围：已登录用户可见所有活动项目；不具备用户级项目成员权限。`baseline_code:{project_id}` 计数器缺行返回 409；后续需在项目初始化流程中创建计数器行，当前不会自动创建。
- `tc_ids` 和 `fp_ids` 可去重；功能点展开得到的已批准用例与手动用例取并集，所有最终条目仍逐条校验同项目、已批准、未退役和 current_version 对应版本行。

## 冻结时实际执行的 SQL
```sql
UPDATE regression_baseline_items SET tc_version=?,snapshot_json=?,snapshot_hash=?,updated_at=?
 WHERE project_id=? AND baseline_id=? AND tc_id=?
 AND EXISTS (SELECT 1 FROM regression_baselines WHERE id=? AND project_id=? AND state='draft');
UPDATE regression_baselines SET state='frozen',manifest_hash=?,data_manifest_json=?,frozen_by=?,frozen_at=?,updated_at=?
 WHERE id=? AND project_id=? AND state='draft';
```
- 同一 batch 还执行状态/用例守卫与 freeze 审计；上面是写入快照和清单的两类实际语句。另有 `INSERT ... WHERE EXISTS (... state='draft')` 增项守卫。

## 等效 Python 复算
```python
import hashlib, sqlite3, sys
c = sqlite3.connect(sys.argv[1])
rows = c.execute("SELECT tc_id,tc_version,snapshot_json,snapshot_hash FROM regression_baseline_items WHERE baseline_id=? ORDER BY tc_id", (int(sys.argv[2]),)).fetchall()
lines = []
for tc_id, version, snapshot_json, stored in rows:
    digest = hashlib.sha256(snapshot_json.encode('utf-8')).hexdigest()
    assert digest == stored
    print('snapshot', digest)
    lines.append(f'{tc_id}:{version}:{digest}')
manifest = hashlib.sha256('\n'.join(lines).encode('utf-8')).hexdigest()
assert manifest == c.execute('SELECT manifest_hash FROM regression_baselines WHERE id=?', (int(sys.argv[2]),)).fetchone()[0]
print('manifest', manifest)
```
