## 接口与交互自查
| 交互 | 方法及路径 | payload / 参数 |
|---|---|---|
| 项目栏、用户与项目列表 | GET `/api/projects`、`/api/me`、`/api/bootstrap` | 无；沿用 PoolUI 与登录跳转 |
| 功能点列表与筛选 | GET `/api/feature-points?project_id=N[&status=active\|pending\|retired]` | 默认省略 status |
| 新建功能点 | POST `/api/feature-points` | `{project_id,title,description}` |
| 编辑功能点 | PATCH `/api/feature-points/:id` | `{title,description,status}`，status 为 active/pending |
| 功能点退役/恢复 | POST `/api/feature-points/:id/retire`、`/revive` | 无 body，二次确认 |
| 用例详情/功能点展示 | GET `/api/testcases/:id` | 顶层 `feature_points`、`retired`；用 `tc.project_id` 定位项目 |
| 加载可选功能点 | GET `/api/feature-points?project_id=N` | 后端默认排除 retired |
| 保存用例功能点 | PUT `/api/testcases/:id/features` | `{fp_ids:[...]}`，最多 90 项，可为空 |
| 编辑用例 | PATCH `/api/testcases/:id` | `{expected_version,title,steps_md,risk,ctype,related_req,change_summary}`；已批准时本地校验摘要 |
| 用例退役/恢复 | POST `/api/testcases/:id/retire`、`/revive` | 无 body，二次确认 |
| 查看历史 | GET `/api/testcases/:id/versions` | 展示 version、change_summary、author、created_at、折叠 steps_md |
| 原执行录入 | PUT `/api/testcases/:id/execution` | `{release_id,result,conclusion,dev_ref,ev_ref}`；沿用实际旧路径和 legacy 行为 |
- 所有新接口操作均展示后端 `error`；新页面对网络故障提供提示。历史步骤用 HTML 转义后放入 `<pre>`。

- `init` 项目选择回调增加 PoolUI 项目同步和新建项目选择同步；`loadList`、`refreshReqOptions` 与新建用例按钮/提交函数未改，原 POST 字段不变。

- `saveTc` 增加已批准时的非空摘要校验，draft 仍选填，原 PATCH 字段、版本乐观锁保留。
- `approve`、`unapprove`、`saveExec` 代码未改；执行的真实旧路由是 `/execution`，不是预核描述中的 `/exec`。
- `delTc` 仍调用原 DELETE 和确认框，新增错误展示，只在成功时关闭抽屉，避免忽略后端 409。
