> 本文回答检查员的第四个问题：**本机构这一套配置是怎么配的、依据什么、由谁批准的**（《药物临床试验计算机化系统和电子数据指导原则》"试验特定配置和定制"一节：配置应当预先制定并详细记录，其变更应当经批准并可获得）。本文只描述**配置的机制与取值登记**，不声明验证已完成；配置取值对不对由机构批准，配置生效与否由第 6 章快照与第 7 章对账证明。

## 1 目的与范围

### 1.1 目的

1. 把本机构上线所依赖的全部配置资产（七类）与其版本链语义、发布方式、生效判定固化为一份经批准的说明书，使"系统按什么规则运行"在检查时可被直接举证。
2. 承载指导原则要求的"试验特定配置和定制"记录，并作为 `URS-T` 试验特定配置需求条目（CSV-02 第 6 章）的取值落点——需求与取值不分散在两处口径。
3. 为 CSV-13 变更控制提供配置基线：任何配置变更都以"快照差异 + 影响面 + 再验证范围"三件为准入条件。
4. 证明配置变更不破坏在途单据（第 8 章版本锁定），这是"整个试验过程中系统始终处于验证有效状态"在配置面的成立条件。

### 1.2 纳入范围

| 纳入 | 说明 |
|---|---|

| 政策键取值与理由 | 第 5 章清单，逐条记录取值、依据与复核时点 |
| 生效快照与一致性 | 第 6 章快照登记表、第 7 章配置体检对账口径 |

### 1.3 不纳入范围

| 不纳入 | 由谁承载 |
|---|---|
| 需求本身（要什么、验收判据） | CSV-02 用户需求说明 |

| 配置的测试用例与执行结果 | CSV-07 运行确认、CSV-09 流程确认、CSV-10 集成验证 |
| 院内既有制度原文（SOP、伦理章程、经费制度） | 机构受控文件体系；本文只登记"该制度落在哪个配置资产与哪个取值"，不抄录制度正文 |
| 业务数据（项目、试验参与者、经费台账等） | 各业务域的库内事实与导出件；本文一律不登记业务数据内容 |

### 1.4 填写纪律

- 全部填写位使用 `〔待填〕`；"不适用"显式写 `N/A + 理由`。
- 示意行一律使用中性占位（`〔本机构流程码〕`、`〔本机构节点名〕`），**不得虚构机构制度内容**；正式填写时由机构按自身 SOP 逐行替换并署批准号。
- 本文不出现机构名称、账号、口令、令牌、密钥、连接串、网络地址与端口号，不出现数据库结构变更编号。
- 机构专属差异一律以"本机构取值"表述，禁止写成"某类医院的通常做法"。

## 3 配置资产总览（七类）

七类资产的共同约束：**每一类都是"界面可配、发布生效、版本可追、导出可举证"的独立配置对象**；配置改动一律经机构授权人员在页面执行发布动作并留名，不允许以脚本或数据订正代替机构批准（CSV-01 第 8.3 节纪律④）。跨院差异一律落在配置里，不落代码分支。

### 3.1 字典与编号规则

| 维度 | 说明 |
|---|---|
| 作用 | 字典中心承载全站的受控枚举（试验类型、分期、审查类别、审查方式、结论与决定用语、访视类型、处置类型、专业组、材料语义键词表等），是表单选项、流程分档、变体匹配与体检校验的共同词表；编号配置承载各域编号规则与取号对象（项目编号、伦理批件号、独立意见号、受理号、合同号、经费号、人遗号、SAE 号、病历/文书与药品类编号等），规则由分段（年份/类型码/科室码/顺序号/固定文本）与顺序号重置策略（按年、按月、不重置、按项目作用域）组成，取号对象可按维度指向专门规则或回落默认规则 |
| 版本链语义 | 字典条目与编号规则均带启用/停用态与版本；取号只认已发布的规则词根，指向不存在或已净库的规则即拒绝并抛业务错误（不静默回落）。顺序号计数器与规则版本分离：升版规则格式不重置计数器，重置策略变更须单独声明 |
| 发布方式 | 在字典中心/编号规则页保存草稿后执行发布；发布前由配置体检做引用完整性校验（表单字段引用的字典是否存在、取号对象是否指向有效规则、规则是否漏配编号段） |
| 生效判定 | 已发布且体检无阻断项即生效；新发起的业务对象即时取用新值，已生成的编号不回改 |
| 导出出口 | 字典清单导出（字典—条目—启用态—被引用方）、编号规则与取号对象绑定导出、编号使用台账（已发号清单）；均可作为快照件 |
| 变更影响面 | 字典条目改名或停用影响：表单选项枚举、变体匹配维度、审查类别路由、材料语义键归档落点；编号规则改动影响：后续所有取号的格式与该域文书编号，**不影响已发号**。字典"删除"须先验引用方，被引用即阻断 |

### 3.2 表单方案

| 维度 | 说明 |
|---|---|
| 作用 | 表单方案（form scheme）是字段定义的事实源，承载字段集合、类型、必填与校验、条件显隐、跨阶段取值来源、选项提供者引用、标签形制；既用作递交页申请/登记表，也用作审批节点的办理工作表 |
| 版本链语义 | 草稿→发布→停用→升版；同一方案族可派生（继承父方案字段再增改），派生链层数有上限且不得成环；被流程引用的方案若为草稿或已停用，引用即视为未生效 |
| 发布方式 | 表单配置页内保存草稿、执行发布；发布前体检校验字段引用的字典是否存在、取值来源方案是否已发布、跨阶段引用的上游字段是否在册、选项源是否两端一致 |
| 生效判定 | 页面渲染与工作表填写一律读取已发布版本的字段定义；**表单字段的唯一事实源是后端已发布方案**，前端展示随其后，不存在"前端字段比后端多"的合法状态 |
| 导出出口 | 表单方案清单导出（方案—版本—状态—字段数—被哪些流程节点挂靠）、单方案字段明细导出（含校验与显隐规则）、已填数据导出（含填写人、时间、来源节点） |
| 变更影响面 | 字段增删改名影响：在途实例已填数据的读取与回看（按实例锁定版本渲染，见第 8 章）、跨阶段复用与自动归档的取值来源、配置体检的上游引用判定、报表列。**"选项提供者引用"与"字典引用"是两族不同来源**：字典族可枚举并可转为静态选项；外部数据源族（人员、企业目录、业务对象等）只显示中文来源名，不可转静态，转静态即造成名单固化 |

### 3.3 材料清单方案

| 维度 | 说明 |
|---|---|
| 作用 | 定义某类递交应备哪些材料、每项的必传性与份数上限、是否要求版本号与文件日期、该环节的符合性审查方式，以及办结后需机构回传的件与收口角色；是"齐不齐"与"行不行"两条轴的载体 |
| 版本链语义 | 与表单方案同族语义（草稿→发布→停用→升版、支持派生继承）；同一节点可按类型/分期/审查对象配置多本清单变体并设默认方案 |
| 发布方式 | 材料清单配置页发布；体检校验条目绑定键是否齐备且节点内唯一、引用的父方案是否已发布、变体适用条件维度是否在字典中登记、变体是否覆盖全部字典取值且无重复条件、回传件的归档语义键是否在词表内、必传回传件是否有可上传的角色 |
| 生效判定 | 发起与递交时读取实例锁定版本的清单；**齐备性（未递交/已递交/版本待补）由系统计算，符合性（未判定/符合/不符合）由审查人判定并落判定台账，两条轴互不覆盖**；符合性判定是否阻断通过型动作由政策键（见第 5 章）决定 |
| 导出出口 | 清单方案导出（方案—节点—条目—必传—份数上限—审查方式—回传件）、项目材料齐备性台账导出、符合性判定记录导出（判定人、时间、结论、理由） |
| 变更影响面 | 影响：递交闸是否放行、办结封口与已消费件禁撤换的判定集合、TMF 归档落点、待办齐备提示；对已办结单据**不回改历史判定**，需重判走更正/复审 |

### 3.4 流程定义

| 维度 | 说明 |
|---|---|
| 作用 | 定义每条业务链的节点集合、节点顺序、办理角色、可用动作（通过型/终止型/回退型）、可退回去向、节点前置条件与跳过条件、工作表模式、挂靠表单与材料方案、编号取号引用、出文触发、待办落地页面、会签完成阈值与落地节点 |
| 版本链语义 | 同一流程码可有多版本，`(code, version)` 全局唯一且**不排除已停用/已软删行**，因此取新版本号必须看该流程码的全量历史版本；发布后旧版本转停用，升版生成新版本行而非原地改写。实例在发起时锁定版本 |
| 发布方式 | 流程设计器编辑→保存→发布；发布时执行服务端硬校验（衔接规则引用的通知事件必须已发布等），且**设计器保存会整段重写节点配置**——凡设计器界面不暴露、只在数据脚本里写过的节点字段，会在下一次发布时被复原，因此此类字段必须有设计器入口（第 7.3 节风险） |
| 生效判定 | 新发起实例用最新已发布版本；在途实例继续按锁定版本运行（第 8 章） |
| 导出出口 | 流程定义清单导出（流程码—版本—状态—发布人—发布时间）、单版本节点表导出（节点/角色/动作/退回/前置/工作表/表单/清单/取号/出文/时限）、版本链与节点链冒烟输出件 |
| 变更影响面 | 影响：待办生成与可见范围、办理权、推进闸、出文与取号、TMF 归档触发、通知投递、报表口径。**节点配置的数据补丁必须覆盖该流程码的全部版本行**，否则锁定在旧版本的在途实例永远等不到该改动 |

### 3.5 文书模板

| 维度 | 说明 |
|---|---|
| 作用 | 定义对外出文文书（批件、意见书、受理与通知类文书、合同与经费单据等）的版式与变量占位符，占位符取数来源为表单字段、工作表字段、项目档案与节点动态取号；并定义签发件的水印与受控版文字 |
| 版本链语义 | 模板带类别、版本与状态；同一文书可配置多模板按条件分流；已出文书与其所用模板版本绑定，模板升版不追溯改写已出件 |
| 发布方式 | 文书模板配置页编辑与发布；出文时机与触发节点解耦（可在同一节点配置是否出文、出哪一类） |
| 生效判定 | 下一次触发出文时使用已发布模板；重出同号文书不覆盖原件，以新行留痕；PDF 伴生件与水印属外部处理产物，不进办理事务，中间态在页面显式可见并可重跑 |
| 导出出口 | 模板清单导出（模板—类别—版本—状态—引用变量清单）、文书台账导出（文书号—项目—节点—生成时间—生成人—状态—伴生件状态）、样张渲染件 |
| 变更影响面 | 影响：对外文书文字与法律效力表述、批件与意见书分流、送达与公示面内容、迎检包文书完整性。模板变量改名会让渲染取空——须以"渲染样张 + 变量对账"双件确认后再发布 |

### 3.6 政策包与政策键

| 维度 | 说明 |
|---|---|
| 作用 | 把跨机构、跨项目类型的制度差异收敛为**少量结构化开关**（按业务阶段分包，一屏一包），覆盖递交顺序与前置门、审查方式路由与频率、批件有效期、收费与票据、纸质与介质要求、结题与归档、药房贮存与发放、经费拨付与税额、安全性报告时限、集成模式等；布尔/枚举/数值/文本四型，枚举候选界面可见可搜索，禁止用 1/0、空值或自由文本表达布尔 |
| 版本链语义 | 每包独立的状态与版本；改动先进草稿、发布后生效；"未配置"与"配置为否"是两个不同状态，前者在体检中报黄 |
| 发布方式 | 政策中心逐包发布（可整包回退到基线）；发布前服务端执行两类校验：**数值区间校验**（法规下限以最小值固化）与**组合冲突校验**（开关间前置依赖、互斥对、跨包死区），冲突即阻断；合规红线项以"锁定 + 依据文本"呈现为只读，界面不可关闭 |
| 生效判定 | 判定发生在读取时：已发布值即当前生效值，新发起与尚未走到判定Branch的动作取新值，已推进的历史动作不回改；存在未发布改动时体检报"页面显示与实际生效不一致" |
| 导出出口 | 政策包取值导出（包—键—类型—出厂基线—当前值—是否偏离—是否锁定—依据），偏离基线项单独成列即"一屏 diff" |
| 变更影响面 | 影响：流程是否插节点、闸是否阻断、待办是否生成、文书是否加水印、收费是否计、接口是否调用、时限阈值与提醒。**跨院差异一律落政策键**，不允许在流程或表单里做院别硬编码分支 |

### 3.7 角色与权限矩阵

| 维度 | 说明 |
|---|---|
| 作用 | 三族配置共同决定"谁能看见什么、能点什么"：① 角色与用户—角色—机构归属关系；② 功能码体系（页面入口码与后端调用码两层，父码挂所属页面菜单）与角色—码授权；③ 数据范围档位（各业务域 × 七档：全部/院区/组/项目/分派/本人/无）与项目授权分工表 |
| 版本链语义 | 角色与授权以当前库态为准、每次变更留稽查轨迹；数据范围矩阵按角色—域—档位三元组记录，档位可选范围由各域注册表唯一承载，界面与后端同源校验；项目授权分工表带版本链与签署状态 |
| 发布方式 | 用户/角色/授权在系统管理页维护；功能码与授权由版本发布内置（新增码与镜像授权同轮生效，只建码不授权即按钮对所有人消失）；数据范围矩阵与授权分工表由机构授权人员配置并电子签 |
| 生效判定 | 三套判定口径不得混用：**功能码按激活角色判定**（页面入口与后端调用闸）；**待办可见性与办理权按该用户全部角色的并集 ∪ 分派/协办名单判定**（不认激活角色）；**数据范围按全部角色中最宽档判定**。季度权限审查表为运行期生效复核出口 |
| 导出出口 | 系统资源台账（端点对账：受保护/自助/裸写/公开，裸写必须为 0，未被引用的码逐个归因）、角色—码矩阵与持有者名单、角色—档位矩阵、权限季度审查表、项目授权分工表签署链 |
| 变更影响面 | 影响：页面可见性、待办归属、可点动作、列表行集与单条可见性、导出字段是否脱敏。**分派/委派型角色必须三件同族补齐**（该域功能读码 + 该域至少分派档 + 单条抬头读判据），否则出现"看得见待办、点进去空白" |

### 6.2 快照必须由页面导出、不得手工誊抄

1. **取得方式**：每一行快照的取值来自对应配置页的导出出口（见第 3 章各资产"导出出口"行）或系统内台账页导出；导出件本身作为 `EV` 证据件入档，登记**页面路径、导出时点、执行人**。
2. **禁止**：从聊天记录、实施方案附件、Excel 汇总或口头口径抄录版本号与取值——这类值无法证明"系统里当下就是这个配置"。
3. **一致性判定**：把导出件中的取值列与第 5 章批准值逐行比对，一致写"一致"；不一致写"差异 + 差异内容 + 处置（改配置或走变更单改批准值）+ 缺陷/变更号"。
4. **可再生**：快照件必须能在同一实例、同一权限下再次导出并复现，以支撑年度回顾与变更前后对比。
5. **完整性**：导出件不得只截首页；行数为 0 或计数为 0 时，先确认数据装载是否完成（配置数据未加载完成时体检页会显示 0 项，属"未检查"而非"全部通过"），再作结论。

## 7 配置与库内一致性对账

### 7.1 三方对账模型

配置的一致性按"配置—引用—落库"三方对账，任一方向不成立即为缺陷：

| 方向 | 对什么 | 不成立的后果 | 承载判据 |
|---|---|---|---|
| 配置 → 引用 | 被流程/表单/清单/文书引用的下游对象是否存在、是否已发布、条件维度是否在字典中登记、派生链是否成环或超层 | 使用时静默回落、节点永不跳过、清单条目无法挂接上传件、表单渲染取不到方案 | 配置体检页的引用完整性与配置未完成类问题 |
| 引用 → 配置 | 页面与文档声明使用的配置项是否都在册（含本文第 5 章键位与第 6 章快照行） | 检查时"说的和配的不是一回事" | 本文快照与页面导出件比对 |
| 配置 → 落库 | 库内当前态与批准值、与出厂配置包文本是否一致；已发布配置是否真被读取 | 已批准值未生效、库内漂移 | 快照导出件 + 落库态对账（含出厂配置一致性校验输出件作为 `EV`） |
| 权限面 | 写接口是否全部受功能码保护、数据范围档位是否全部接线、建码是否同轮播授权 | 出现"点不到的写"或越权可见 | 系统资源台账 + 两个覆盖率静态对账口（基线只准降） |

### 7.2 差异即缺陷

对账发现的每一项差异，登记为 `ISS-`（运行期）或 `DEV-`（验证期），并按第 10 章走变更判定。判据不是"看起来不影响使用"，而是"**该差异是否使系统运行规则偏离经机构批准值**"。

### 7.3 "界面不暴露的字段会被下一次发布复原"——风险与规避

**风险**：流程定义等配置对象的整段内容由设计器在保存/发布时重写。凡只在数据脚本里写入、而设计器界面没有对应编辑入口的字段（例如节点的工作表模式、某类动作开关），在该流程下一次被任何人保存或升版时会被**静默写回默认值**，页面不报错、不提示、不留差异记录。同类风险还出现在"按最新版本回填"的配置补丁上：在途实例按发起时锁定的版本运行，只改最新版本的补丁对它们永远不生效。

**规避四条（编制与运行期一律执行）**：

1. **字段入口齐备**：任何需要长期存在的配置字段，必须在设计器/配置页有可见可编辑的入口；只允许"两侧都有入口"的字段进入配置基线，否则该字段不作为配置事实。
2. **补丁覆盖全部版本行**：对已发布配置做数据层修正时，必须遍历该流程码/该方案码家族的**全部未软删版本行**，不得只改最新一行。
3. **发布即重取快照**：任何配置发布动作之后，重新导出第 6 章受影响资产快照，并与批准值做一致性列，差异进对账表；这是"发布后是否复原"的唯一可观测手段。
4. **体检常驻阻断**：把配置体检页作为发布前必经步骤，阻断项为 0 才允许进入下一阶段的验证执行（对应 CSV-01 第 6 章 P2 出口判据"配置体检对账无差异"）。

## 8 在途实例与版本锁定说明

1. **锁定规则**：每一条业务流程实例在**发起时**固化其使用的流程定义版本，此后该实例的节点解析、动作集合、工作表与材料清单、前置条件与出文触发全部按锁定版本执行；配置升版只改变**之后新发起**的实例。
2. **表单与清单同理**：实例回看按锁定版本渲染字段与清单条目，历史已填值不因方案升版而被重新解释。
3. **政策键不同**：政策键取值不带实例版本快照，判定发生在读取时点。因此**政策键变更会影响在途实例的后续动作**——变更评估必须先回答"哪些在途实例的哪个未办节点会被新值改变行为"，这是第 10 章配置变更评估的必查项。
4. **编号不回改**：已发出的编号不因规则升版而改变；取号对象改动只影响后续取号。
5. **权限即时生效**：角色、功能码与数据档位变更对当前会话按下一次判定即时生效，不存在版本锁定；因此权限类变更须安排在业务低峰并同步更新可见范围说明。
6. **评估清单（每次配置变更前逐项回答）**：
   - 受影响的流程码有哪些版本在册？在途实例各停在哪个版本？
   - 需要覆盖全部版本行吗？（第 7.3 节规避 2）
   - 政策键变更是否改变在途实例未办节点的行为？
   - 是否影响已办结单据的可回看性、已出文书的同号重出、已封口的材料？
   - 存量数据是否需要回填？回填是否用增量幂等方式实施，**不改写已应用的结构变更**？
   - 再验证范围（哪些用例必重跑）是否与 RTM 同步更新？
